FAQ

Questions are grouped for XSIC-wide operations: workflow, freshness, route interpretation, service limits, and coverage boundaries.

XSIC workflow and app roles

What is XSIC in one line?
XSIC is a four-app decision console for XRPL execution checks: impact estimate, liquidity posture, flow regime, and structural exposure.
What order should operators use?
Default order is Sell Impact → Liquidity Pulse → Flow Alert → Exposure Graph. This sequence reduces single-snapshot bias.
Can one app be used alone?
Yes, but single-app reads are lower confidence. XSIC is designed for cross-checking disagreement before execution.

Data freshness and availability

How fresh is data across XSIC?
Freshness differs by app and endpoint path. Always verify timestamp, state badge, and any stale/partial markers shown in-app.
What does stale, partial, or unavailable mean?
Stale means last readable state is older than target cadence; partial means some upstream paths degraded; unavailable means required data could not be served.
Should execution continue during degraded state?
That is a user decision, but operationally the safer baseline is smaller size, slower cadence, or pause until key checks recover.

Price guarantees and route differences

Does XSIC guarantee execution price or fill amount?
No. XSIC provides estimates and context, not guarantees. Realized outcomes can move between quote time and execution time.
Why can route mix change quickly?
Orderbook queue changes, AMM state changes, and concurrent activity can alter best path composition in short intervals.
How should route disagreement between checks be read?
Treat disagreement as risk signal. Re-run impact, confirm liquidity persistence, and avoid assuming the earlier route remains executable.

Model limits and coverage

Are XSIC outputs predictions?
No. XSIC uses observed state and derived estimates. It is decision support, not deterministic forecasting.
Does Exposure Graph represent immediate tradability?
No. It shows structural concentration and dependency, which must be combined with live impact and liquidity checks.
Is every token/pair covered equally?
No. Coverage depends on app presets, endpoint reachability, and data pipeline scope at the time of query.

Security and operational safety

Does XSIC require wallet seeds or private keys?
No. Normal analytics usage should never require sharing secret credentials.
What minimum safety practice is recommended?
Never paste secret data into web forms, and always confirm URLs plus on-page address strings before sending funds.
Where should incidents or bugs be reported?
Report with reproducible context: URL, timestamp, selected pair/preset, visible state badges, and observed vs expected behavior.
