XSIC

Project details

Credits

XSIC combines multiple XRPL analysis apps in one console. This page clarifies data lineage, infrastructure components, runtime libraries, and maintenance context.

Data sources

  • XRPL ledger and market data retrieved through project API functions (orderbook, AMM, account, trustline, and related transaction views).
  • XSIC-managed derived snapshots for flow-history and preset bundles shipped from repository data files and API endpoints.
  • Per-app timestamps and state badges are the canonical freshness indicator when interpreting outputs.

Infrastructure

  • Cloudflare Workers / Pages Functions runtime for request handling and XRPL data normalization.
  • Static front-end hosting with shared navigation/status components and app-specific modules.
  • Operational scripts in the repository for snapshot updates, diagnostics, and endpoint checks.

Libraries and runtime

  • Vanilla HTML/CSS/JavaScript UI architecture, no monolithic front-end framework dependency.
  • Node.js/npm toolchain and declared package dependencies in repository manifests.
  • XRPL ecosystem libraries and internal utility modules used by apps and server functions.

Reference documentation

  • Methods and FAQ pages define interpretation rules and known limits for each app.
  • Disclaimer page defines legal/operational boundary conditions for tool usage.
  • Specification and audit notes under /docs provide implementation context for ongoing updates.

Maintenance context

  • Maintained by Badjoke-lab with emphasis on reliability, bounded interpretation, and operational clarity.
  • Prioritization is driven by data integrity issues, user-reproducible incidents, and cross-app consistency improvements.
  • Issue reports are most actionable when they include URL, timestamp, selected pair/preset, and visible status labels.
